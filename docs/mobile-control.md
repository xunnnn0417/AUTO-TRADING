# 手機控制（連線先行版）

手機是操作入口；交易資料、試算表寫入、原有核對及平台操作均由電腦端執行。
不需要在電腦再輸入一次。手機輸入先同步為共用草稿，更新／填入時沿用原有套用流程。

## 開啟方式

1. 電腦完成方案、交易平台綁定與校準。
2. 「管理 → 手機連線」開啟連線；預設不開啟。
3. 尚未設定外網時，可用「本機預覽」檢查頁面。
4. 手機外網連線需管理者提供 HTTPS 入口，將同一站點的 HTTP 與 WebSocket
   轉送到電腦的 `127.0.0.1:8765`，並保留原 Host、Origin 及 Cookie。
   在電腦填入該 HTTPS 站點網址後重新開啟連線。
5. 首次輸入電腦產生的八位配對碼，五分鐘內有效、僅能使用一次；五次錯誤後須重新產生。
   之後直接按「連線」。裝置授權保存 180 天，可由電腦移除。

目前沒有自動建立外網服務、設定路由器、安裝轉送工具或手機推播。
`127.0.0.1` 只代表本機，不能把本機預覽網址直接交給另一台手機使用。
HTTPS 入口的部署、服務帳戶與實際手機連線仍須另外完成及驗收。

## 範圍與資料同步

- 首頁：已設定方案、階段、方向、預期 SL、餘額、每日盈虧、更新、填入兩邊、手數與帳號進度。
- 「其他交易操作」預設收起：單邊填入、查看止盈止損、同步、進場點位及交易選項。
- 消息共用電腦已取得的事件，不另建立一套抓取排程。
- 不提供試算表設定、校準、視窗綁定、檔案存取、終端機或任意滑鼠／鍵盤命令。
- 手機修改後由電腦回報最新草稿及已套用值；兩者分開顯示。
- 執行中／電腦鎖定／有未完成確認時，其他交易輸入不可操作。
- 交易參數在接收後又有改動，本次操作會拒絕；不悄悄使用另一份數值。
- 原有交易確認會傳回手機供選擇，並不因遠端而自動略過；無法呈現的輸入視窗會明示需電腦處理。
- 完成、未執行、失敗、結果待核對分開顯示；成交成功必須有原流程的確認結果。

## 連線與安全邊界

- 使用既有 PySide6 的 Qt Network／WebSockets，不新增下載執行的套件。
- 僅監聽 loopback；外網需明確設定 HTTPS 轉送，不可直接公開明文連接埠。
- 網頁、Origin 與 Host 僅接受指定站點；配對授權使用 HttpOnly／SameSite Cookie，
  外網加 Secure。JavaScript 不持有裝置憑證，不儲存於 localStorage。
- 裝置只保存高隨機憑證的雜湊；配對碼及 Cookie 不寫操作日誌或發布包。
- 操作 ID 在本機獨立資料庫保存；同 ID 不執行第二次，重啟後未完成操作標示未知，永不自動重送。
- 主動斷線不代表已停止執行；重新連線先查結果。停止按鈕沿用原有緊急停止，不會自行平倉。
- 私人裝置授權與操作結果留在電腦資料目錄，不放入方案、不上傳 GitHub。

## 工程驗證

既有 unittest 流程：

```text
python -m unittest discover -s tests -p test_mobile_remote.py -v
python -m unittest discover -s tests -p "test_*.py" -q
python -m compileall -q trading_helper
```

使用隔離暫存設定、loopback 測試連線與模擬操作；不得把測試訊息當作實際成交驗收。
